## Verified Next 16.3.5 conventions (read from `node_modules/next/dist/docs/`)

Paths below are relative to `node_modules/next/dist/docs/01-app/`.

- **`proxy.ts` replaces `middleware.ts`.** Put it at the project root and export `proxy(request: NextRequest)`, or a default export. It always runs on Node; setting `runtime` throws. `config.matcher` must be static. See `03-api-reference/03-file-conventions/proxy.md` and `02-guides/upgrading/version-16.md` (section "middleware to proxy"). Ours uses a positive matcher of app paths only, so `/`, `/api`, `/_next`, `/p/*`, auth pages and static files never run proxy.
- **Async request APIs only.** Use `await cookies()`, `await headers()`, `await props.params` and `await props.searchParams`; synchronous access is gone. See `upgrading/version-16.md` and `03-api-reference/04-functions/cookies.md`. Server Components can read cookies but cannot set them.
- **`PageProps<'/route'>` and `LayoutProps<'/route'>` are global.** Don't import them. They are generated by `next dev`, `next build` or `next typegen`. See `03-file-conventions/page.md` and `layout.md`.
- **Route groups.** `(folder)` stays out of the URL. Two groups must not resolve to the same path. See `03-file-conventions/route-groups.md`.
- **`redirect()` and `notFound()` throw (type `never`).** Call them outside `try`. `redirect` returns a 307. In client event handlers, use `useRouter` instead. See `04-functions/redirect.md` and `not-found.md`.
- **`error.tsx` gets `{ error, retry }`.** `retry` is stable in 16.3 and re-fetches, while `reset` does not. An error boundary does not catch errors from the layout in its own segment. See `03-file-conventions/error.md`.
- **Auth.** Proxy does only an optimistic cookie check. A `server-only` DAL does the real one, with `verifySession()` wrapped in React `cache`. Layouts don't re-render on client navigation, so pages that read protected data should call `verifySession()` as well. See `02-guides/authentication.md` ("Optimistic checks with Proxy", "Creating a DAL", "Layouts and auth checks").
- **Server `fetch` caching is opt-in.** The default is "auto no cache", but a fetch in a static route runs once at build. Pass `cache: "no-store"` for per-request data. See `04-functions/fetch.md`.
- **`rewrites()` in `next.config.ts`.** The array form runs after the filesystem and before dynamic routes. The destination is resolved at build time, so set `BACKEND_URL` when running `next build`, not only at `next start`. See `05-config/01-next-config-js/rewrites.md`.
  - The proxy timeout is not in the docs, but `experimental.proxyTimeout` (ms, default 30000) is typed and schema-validated in `dist/server/config-shared.d.ts` and used by `dist/server/lib/router-utils/proxy-request.js`. We set it to 120 s.
- **Metadata `robots`.** Use `robots: { index: false, follow: false }` in `metadata` (`04-functions/generate-metadata.md`). The `(app)` layout, the auth pages and `/p/[token]` are noindex.

## Project conventions

- **Route groups:**
  - `app/(marketing)` holds the landing page and its ambient and cursor chrome.
  - `(auth)` holds login and signup.
  - `(app)` is the authenticated shell, via `verifySession()` → `AppShell` + `MeProvider`.
  - `(public)/p/[token]` holds the client proposals.
- **Browser calls** go through `api<T>()` in `lib/api/client.ts`, which fetches the same-origin `/api/v1` with the `X-JetStream-Client: web` header and throws `ApiError`.
- **Server calls** go through `serverApi<T>()` in `lib/api/server.ts`, which calls `BACKEND_URL` directly with `Authorization: Bearer <js_session>`.
- **API types.** `lib/api/types.ts` is hand-written until `npm run gen:api` creates `lib/api/schema.d.ts`.
- **Gate:** `npm run typecheck`, `npm run lint` and `npm run build`.
